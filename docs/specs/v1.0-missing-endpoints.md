# Spec — v1.0 后端缺失接口补全

## Problem Statement

`smart-learning-agent` 前端 8 个页面（Review / Assessment / Tracking / Profile 等）当前只能靠 Mock 数据运行。后端虽然已经交付认证、作业批改、仪表盘、掌握度、错题本和分层练习，但要打通前端页面，还需要补齐：

- 复盘页所需的复盘报告接口；
- 评估页所需的阶段考核接口（已经在 `stage_assessment` 完成）；
- 追踪页所需的 4 个长期追踪接口；
- 个人中心页所需的统计与偏好接口；
- `/api/auth/me` 上补充创建/最后登录时间；
- `/api/wrong-questions` 的 `Question` 中补充 `created_at`，让热力图能按天分组。

需求清单已经在仓库外的 `后端缺失接口需求清单(3).md` 描述完，本 spec 不再重复字段细节，只锁定接口契约、模块归属、测试与不在范围。

## Solution

沿用内核插件架构，把缺失的接口按能力聚合到 **已有插件 `learning_insights`** 与 **已有认证模块**：

- `learning_insights` 负责复盘报告、长期追踪、个人统计与偏好；这些功能已经在其声明的 capability 列表里（`review_reports`、`learning_tracking`、`profile_statistics`），继续扩展最自然。
- `auth.services.serialize_user` 增加 `created_at`、`last_login_at`，并在 `auth.routes.login` 成功路径上写入 `last_login_at`，对应一个 Alembic 迁移。
- `assignment_grading.serializers.serialize_question` 同步返回 `created_at`，错题本与作业详情都受益。

数据库方面，新增 `user_preferences` 单行表（按 `user_id` 唯一）保存学习偏好；`users` 表新增 `last_login_at` 列。所有变更都附带 Alembic 迁移。

## User Stories

1. As a 学生，I want to 拉取周期复盘报告（日报/周报/月报/学期报告），so that Review 页能用真实数据替代 Mock。
2. As a 学生，I want to 创建一个阶段评估试卷（专项小测/单元卷/模拟卷/高考专题卷），so that Assessment 页能联动真实生成流程。
3. As a 学生，I want to 查看我的考核列表与单次详情，so that 我能复盘最近评估。
4. As a 学生，I want to 提交整张考卷，so that 后端统一判分并产出 `student_score`。
5. As a 学生，I want to 跨周期对比最近两次得分与知识点掌握度变化，so that 我能看到进步幅度。
6. As a 学生，I want to 查看追踪页的总体掌握度、今日复习量、连续学习天数，so that 顶部卡片真实。
7. As a 学生，I want to 看到知识图谱（按掌握度分 4 档），so that 我能识别薄弱知识点。
8. As a 学生，I want to 查看基于艾宾浩斯曲线的复习计划（今天/7天/14天/30天），so that 我能按时复习。
9. As a 学生，I want to 查看最近 14 天活跃度热力图，so that 我能看到学习节奏。
10. As a 学生，I want to 查看累计错题总数、已掌握/薄弱知识点数、连续学习天数，so that Profile 页统计卡片真实。
11. As a 学生，I want to 保存和读取学习偏好（每日目标、复习时间、难度策略、薄弱提醒开关），so that 我的偏好能被持久化。
12. As a 学生，I want to 在「账号与安全」看到入驻时间和上次登录时间，so that 我能确认账号状态。
13. As a 前端开发者，I want to `wrong-questions` 中的题目自带 `created_at`，so that 热力图可以精确按天聚合。

## Implementation Decisions

### 模块归属

- 新增 4 个追踪端点、`/api/profile/stats`、`/api/profile/preferences` 全部挂在 `learning_insights` 插件下；`learning_insights.plugin.PluginSpec.capabilities` 已经声明了 `review_reports`、`learning_tracking`、`profile_statistics`，本次只扩展路由表与 service。
- `auth` 内核模块扩展 `serialize_user`；`login` 路由在签发 access_token 前写一次 `last_login_at`。
- `assignment_grading.serializers.serialize_question` 返回结构补 `created_at`（受益方：错题本、作业详情、复盘报告聚合）。

### 数据模型

- 新表 `user_preferences`（按 `user_id` 唯一）：
  - `daily_goal INT NOT NULL DEFAULT 20`
  - `review_time VARCHAR(5) NOT NULL DEFAULT '19:30'`
  - `difficulty VARCHAR(16) NOT NULL DEFAULT 'adaptive'`（adaptive/basic/variation/advanced）
  - `weak_reminder BOOLEAN NOT NULL DEFAULT TRUE`
  - `created_at`、`updated_at`（沿用 `TimestampMixin`）
- `users` 表新增 `last_login_at DATETIME NULL`。
- `created_at` 字段已经在 `TimestampMixin` 里，`users.created_at` 一直存在；`last_login_at` 需要 schema 变更与默认值处理（默认 NULL，老用户不回填）。

### API 契约

按需求文档原样落地，所有端点都是 JWT 鉴权 + `ok({...})` 响应外壳，复用 `app.kernel.responses.ok` 与 `app.kernel.auth.dependencies.get_current_user`。

新增端点：

| 方法 + 路径 | 用途 | Service 函数 |
| --- | --- | --- |
| `GET /api/tracking/overview` | 追踪页 3 卡片 | `get_tracking_overview` |
| `GET /api/knowledge-graph` | 标签云图 | `get_knowledge_graph` |
| `GET /api/tracking/review-schedule` | 间隔重复计划 | `get_review_schedule` |
| `GET /api/tracking/activity-heatmap` | 14 天活跃度 | `get_activity_heatmap` |
| `GET /api/profile/stats` | Profile 统计 | `get_profile_stats` |
| `GET /api/profile/preferences` | 读偏好 | `get_profile_preferences` |
| `PUT /api/profile/preferences` | 写偏好 | `update_profile_preferences` |

### 行为细节（已与 spec 对齐）

- `level` 分档：1=≥80、2=60–79、3=40–59、4=<40；`nodes` 按 level 降序 + mastery 升序。
- `review-schedule` 默认按 `pending` 聚合：今天/7 天/14 天/30 天四个桶，今天桶 `active=true`，其他 `false`。返回时按时间升序。
- `activity-heatmap` 默认 14 天，可选 7–30 天；按 `wrong_questions` 与 `assignments` + `practice_tasks` 当天创建量聚合；level 阈值：0=无、1=1–2、2=3–4、3=5–7、4=8+。
- `continuous_days` 来自「最近一次学习活动（错题/作业/练习/考核）至今往前连续每天都有活动」的天数，Profile 与 Tracking 共用同一计算。
- `overall_mastery` = 所有 `MasteryRecord.mastery_score` 的加权平均（按 `correct_count + wrong_count` 加权），无记录则返回 0。
- `mastered_points` = `mastery_score >= 80` 的 `MasteryRecord` 数；`weak_points` = `< 40`。
- `preferences` 写入时校验：`daily_goal ∈ [5,100] 且 5 的倍数`，`review_time` 形如 `^([01]\d|2[0-3]):[0-5]\d$`，`difficulty ∈ {adaptive,basic,variation,advanced}`。

### 测试决策

- 沿用现有 `tests/test_learning_insights_api.py` 风格：用 `TestClient(app)` + 真实 SQLite + `fakeredis`，注册学生后通过接口断言响应结构与数据。
- 每个新接口至少 1 个测试；存在分支的（如 review-schedule 的 pending/overdue/completed，heatmap 的 level 0）补额外测试。
- TDD：先写测试（red），再写 service + route（green），最后只做必要的重构。沿用 plugin 内的导入风格与 `ok(...)` 响应外壳。

### 不在范围

- 第三方账号绑定（手机/邮箱/微信/QQ）：spec 列为后续迭代。
- P3 练习题结构化选项 `options`：本期不动 `layered_practice` 的 `PracticeQuestion`；前端可改纯文本输入框。
- 推送 / 邮件 / 复习提醒定时任务：仅落库用户偏好，不实际触发。
- Alembic 在测试库上的应用：测试用 `Base.metadata.create_all`（`AUTO_CREATE_TABLES=true`），生产用新迁移 `20260723_0004_*`。
